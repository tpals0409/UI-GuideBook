# 로그인 보안 구현·검증 체크리스트

## 0. 적용 기준

- 비밀번호 최소 길이는 NIST SP 800-63B-4 기준이며 제품·보안 합의로 조정한다. 조정 시 값·근거를 기록하고 NIST 기준 충족 여부를 별도로 명시한다.
- 항목 ID는 섹션 이동 후에도 유지한다. 10번의 AUTH-8.1-xx와 11번의 AUTH-8.2-xx는 기존 ID다.
- Must: 해당 기능에 적용되는 필수 릴리스 기준. FAIL·미검증이면 출시를 차단한다.
- Should: 권고 기준. 미적용 시 사유·위험·담당자·개선 기한을 기록한다.
- 이 태그는 본 문서의 운영 기준이며 모든 출처의 규범 수준을 그대로 옮긴 것이 아니다.
- 체크리스트 통과는 특정 감사·인증 충족이나 취약점 부재를 보장하지 않는다.

- [ ] [Must] [AUTH-0-01] 공통 항목은 모든 인증 경로에 적용한다.
- [ ] [Must] [AUTH-0-02] JWT·소셜 로그인·비밀번호 항목은 사용 여부에 따라 추가 적용한다.
- [ ] [Must] [AUTH-0-03] 웹·모바일·관리자·구버전 API·복구 경로를 점검 대상에 포함한다.
- [ ] [Must] [AUTH-0-04] 각 항목에 PASS / FAIL / N/A / 미검증, 구현 위치, 검증 근거를 기록한다.
- [ ] [Must] [AUTH-0-05] N/A에는 적용하지 않는 이유를 기록한다.
- [ ] [Must] [AUTH-0-06] 코드 존재만으로 PASS 처리하지 않는다. 실패·우회·동시 요청을 검증한다.
- [ ] [Must] [AUTH-0-07] 확인하지 못한 항목은 미검증으로 남긴다.

## 1. 공통 — 통신·입력·비밀정보

- [ ] [Must] [AUTH-1-01] 인증 화면과 모든 API에 HTTPS를 적용한다. 프록시 이후 구간도 신뢰 경계에 맞게 보호한다.
- [ ] [Must] [AUTH-1-02] 비밀번호·인증 토큰·세션 ID를 URL에 포함하지 않는다.
- [ ] [Must] [AUTH-1-03] 서버에서 입력 타입·길이·요청 크기를 제한한다.
- [ ] [Must] [AUTH-1-04] 인증 DB 쿼리에 매개변수화된 쿼리 또는 안전한 ORM API를 사용한다.
- [ ] [Must] [AUTH-1-05] 비밀번호·토큰·인증 코드를 로그·APM·에러 추적·분석 도구에서 제외한다.
- [ ] [Must] [AUTH-1-06] 키·시크릿을 코드·저장소·프론트 번들에 포함하지 않는다.
- [ ] [Must] [AUTH-1-07] 운영·개발 환경의 키, 계정, OAuth 설정을 분리한다.
- [ ] [Must] [AUTH-1-08] 인증 의존성의 지원 종료 여부를 확인하고 CI에서 SCA를 실행한다. 적용 가능한 알려진 취약점은 심각도·악용 가능성·도달 가능성으로 판정한다. 미조치 Critical/High는 출시를 차단하며 오탐·비해당 판정은 근거를 남긴다.

- [ ] [Must] [AUTH-1-09] HSTS를 운영 도메인에 적용하고 HTTPS 응답 헤더를 검사한다. includeSubDomains·preload는 하위 도메인 HTTPS 지원 확인 후 적용한다.
- [ ] [Must] [AUTH-1-10] 인증 자격을 포함하는 응답과 민감한 인증 응답에 Cache-Control: no-store를 적용하고 CDN·프록시에서도 캐시되지 않는지 확인한다.
- [ ] [Must] [AUTH-1-11] 모든 로그인·복구 경로의 next·returnUrl은 파싱 후 내부 경로나 명시적 허용 목록으로 검증한다. //외부호스트·인코딩 우회도 거부한다.

## 2. 공통 — 인증·권한·공격 방어

- [ ] [Must] [AUTH-2-01] 보호 API마다 서버에서 인증한다. 프론트 상태와 전달된 사용자 ID·역할을 신뢰하지 않는다.
- [ ] [Must] [AUTH-2-02] 리소스 소유권·역할·테넌트 접근 권한을 별도로 검사한다.
- [ ] [Must] [AUTH-2-03] 누락된 인증 정보, 검증 오류, 인증 저장소 장애 시 접근을 허용하지 않는다.
- [ ] [Must] [AUTH-2-04] 로그인·갱신·복구·인증번호 발급 및 검증에 각각 요청 제한을 적용한다.
- [ ] [Must] [AUTH-2-05] 계정·IP 등 복수 기준을 사용하고, 분산 서버에서도 제한을 공유한다.
- [ ] [Must] [AUTH-2-06] 계정 존재 여부가 메시지·상태 코드·응답 시간 차이로 쉽게 노출되지 않게 한다.
- [ ] [Must] [AUTH-2-07] 계정 잠금이 타인 계정을 마비시키는 수단이 되지 않도록 한다.
- [ ] [Must] [AUTH-2-08] 관리자·고위험 계정에 MFA를 적용한다.
- [ ] [Must] [AUTH-2-09] 이메일 변경·인증 수단 추가·계정 연결·MFA 해제에 최근 재인증을 요구한다. 비밀번호 변경 재인증은 AUTH-8-14에서만 판정한다.
- [ ] [Must] [AUTH-2-10] 계정 정지·탈퇴·권한 회수의 기존 인증 반영 시점을 정의하고 구현한다.

- [ ] [Must] [AUTH-2-11] 회원가입·비밀번호 재설정에도 계정 열거 방지 응답과 요청 제한을 적용한다.
- [ ] [Must] [AUTH-2-12] 비밀번호·이메일·MFA·외부 계정 연결 변경 시 변경 전 검증된 연락처로 보안 알림을 보낸다. 자격 증명은 포함하지 않는다.
- [ ] [Must] [AUTH-2-13] 이메일 변경은 최근 재인증 및 새 이메일 소유 검증 완료 후 확정하고 기존 이메일에 알린다.
- [ ] [Should] [AUTH-2-14] 새 기기·이상 위치 로그인 알림을 제공한다. IP 위치만으로 사용자 신원을 확정하지 않는다.

### 2.1. MFA·OTP·복구 — 해당 기능 사용 시

- [ ] [Must] [AUTH-2.1-01] MFA 완료 전에는 제한된 인증 트랜잭션만 발급하고 일반 보호 API·토큰 갱신을 허용하지 않는다.
- [ ] [Must] [AUTH-2.1-02] 비밀번호 재설정이 MFA를 해제하거나 완료 처리하지 않게 한다. MFA 복구는 별도 소유 확인·감사 로그·사용자 알림을 적용한다.
- [ ] [Must] [AUTH-2.1-03] MFA 등록은 새 인증 수단의 소유 검증 성공 후 활성화한다. 교체·해제는 기존 인증 수단 또는 승인된 복구 절차로 확인한다.
- [ ] [Must] [AUTH-2.1-04] TOTP의 허용 시간 오차를 제한하고 성공한 계정·인증기·시간 스텝을 원자적으로 소비해 동시 요청과 유효기간 내 재사용을 거부한다.
- [ ] [Must] [AUTH-2.1-05] TOTP 공유 비밀은 검증에 필요하므로 암호화 저장하고 접근을 제한한다. 백업 코드는 충분한 난수로 생성해 해시 저장·일회용 소비를 적용한다.
- [ ] [Must] [AUTH-2.1-06] OTP는 계정·목적·트랜잭션에 연결한다. 임의 숫자 코드는 CSPRNG로 생성하고 코드 길이·TTL·시도 상한·재발송 간격을 설정값으로 명시한다.
- [ ] [Must] [AUTH-2.1-07] 자체 발급 숫자 OTP의 기본 정책은 6자리 이상·TTL 5분 이하·트랜잭션당 실패 5회 이하로 설정한다. 서비스별 변경은 위험 근거를 기록한다. TOTP는 해당 프로토콜의 시간 스텝 정책을 적용한다.
- [ ] [Must] [AUTH-2.1-08] MFA·OTP 검증에 별도 계정·IP 요청 제한을 적용한다. 재발송·새 트랜잭션으로 계정 단위 실패 제한이 초기화되지 않게 한다.
- [ ] [Must] [AUTH-2.1-09] 새 OTP 발급 시 이전 코드를 폐기한다. 검증 성공·한도 초과·만료 시 트랜잭션을 종료하고 동시에 여러 요청이 성공하지 않게 한다.

## 3. 공통 — 브라우저·세션

- [ ] [Must] [AUTH-3-01] 인증 쿠키에 HttpOnly, Secure, 흐름에 맞는 SameSite를 설정한다.
- [ ] [Must] [AUTH-3-02] 쿠키의 Domain·Path 범위를 최소화한다.
- [ ] [Must] [AUTH-3-03] 쿠키 기반 인증의 상태 변경 요청에 CSRF 방어를 적용한다.
- [ ] [Must] [AUTH-3-04] GET 요청으로 상태를 변경하지 않는다.
- [ ] [Must] [AUTH-3-05] CORS는 신뢰하는 Origin만 허용한다. CORS를 인증·CSRF 방어의 대체로 사용하지 않는다.
- [ ] [Must] [AUTH-3-06] 출력 이스케이프 등 XSS 방어를 적용한다.
- [ ] [Must] [AUTH-3-07] 장기 인증 자격을 localStorage에 보관하지 않는다.
- [ ] [Must] [AUTH-3-08] 세션 ID는 암호학적으로 안전한 난수로 생성한다.
- [ ] [Must] [AUTH-3-09] 로그인·권한 상승 시 세션 ID를 재발급하고 이전 세션을 폐기한다.
- [ ] [Must] [AUTH-3-10] 유휴 만료·절대 만료를 서버에서 검사한다.
- [ ] [Must] [AUTH-3-11] 로그아웃 시 브라우저 데이터 삭제 외에 서버 측 인증 자격도 폐기한다.
- [ ] [Must] [AUTH-3-12] 계정 탈취 대응을 위한 전체 세션 종료 기능을 마련한다.

- [ ] [Should] [AUTH-3-13] CSP를 적용하고 실제 응답에서 확인한다. CSP를 출력 이스케이프의 대체로 사용하지 않는다.
- [ ] [Must] [AUTH-3-14] Remember me 사용 시 서버에 등록된 별도 장기 자격으로 관리한다. 절대 만료·회전·기기별 폐기·로그아웃 및 비밀번호 변경 반영 시점을 명시한다.

## 4. JWT — 검증·키 관리

- [ ] [Must] [AUTH-4-01] decode 결과로 인증하지 않는다. 검증된 라이브러리로 서명을 검증한다.
- [ ] [Must] [AUTH-4-02] 허용 알고리즘을 서버에서 고정한다. none·알고리즘 혼동을 거부한다.
- [ ] [Must] [AUTH-4-03] 발급자별 허용 키 또는 고정된 HTTPS JWKS 주소를 설정한다. 미등록 발급자·키·알 수 없는 kid는 거부하고 키 조회 실패 시 검증을 생략하지 않는다.
- [ ] [Must] [AUTH-4-04] iss, aud, exp, 사용자 식별 클레임을 필수 검증한다.
- [ ] [Must] [AUTH-4-05] nbf가 있으면 검사하고, 시간 오차 허용 범위를 제한한다.
- [ ] [Must] [AUTH-4-06] 필수 클레임의 누락·잘못된 타입·예상하지 않은 값을 거부한다.
- [ ] [Must] [AUTH-4-07] Access Token·Refresh Token·ID Token의 검증 규칙과 사용처를 분리한다.
- [ ] [Must] [AUTH-4-08] 서명 JWT payload에 비밀번호·시크릿·불필요한 개인정보를 넣지 않는다.
- [ ] [Must] [AUTH-4-09] HMAC 키는 충분한 엔트로피로 생성한다. 비대칭 개인키는 발급 주체만 보유한다.
- [ ] [Must] [AUTH-4-10] kid는 신뢰하는 키 집합에서만 조회한다. 파일 경로·쿼리로 직접 사용하지 않는다.
- [ ] [Must] [AUTH-4-11] 토큰의 jku·x5u·iss를 이용해 임의 URL에서 키나 설정을 가져오지 않는다.
- [ ] [Must] [AUTH-4-12] 키 회전·유출 대응·이전 키 허용 종료 시점을 구현한다.

- [ ] [Must] [AUTH-4-13] 토큰 프로파일이 typ을 정의하면 예상 값을 검증한다. RFC 9068 Access Token은 at+jwt 프로파일을 따른다. typ만으로 용도를 판정하지 않고 aud·발급자·클레임 규칙도 함께 검증한다.

## 5. JWT — 갱신·폐기

- [ ] [Must] [AUTH-5-01] Access Token 만료 시간을 짧게 설정하고 위험도에 따른 근거를 기록한다.
- [ ] [Must] [AUTH-5-02] Refresh Token에 절대 만료·폐기·세션별 관리 정책을 적용한다.
- [ ] [Must] [AUTH-5-03] Refresh Token 회전 또는 송신자 바인딩을 적용한다.
- [ ] [Must] [AUTH-5-04] 자체 발급 Refresh Token을 비교용으로 저장한다면 원문 대신 해시를 저장한다.
- [ ] [Must] [AUTH-5-05] 회전 시 이전 토큰 소비와 새 토큰 발급 상태를 원자적으로 처리한다.
- [ ] [Must] [AUTH-5-06] 이전 Refresh Token 재사용 탐지 시 관련 토큰 계열을 폐기하는 정책을 구현한다.
- [ ] [Must] [AUTH-5-07] 정상적인 동시 갱신·네트워크 재시도의 처리 방식도 정의한다.
- [ ] [Must] [AUTH-5-08] 갱신 시 계정 정지·탈퇴·세션 폐기·현재 권한을 확인한다.
- [ ] [Must] [AUTH-5-09] 로그아웃 시 Refresh Token을 폐기한다.
- [ ] [Must] [AUTH-5-10] 이미 발급한 Access Token의 잔여 유효시간을 명시한다.
- [ ] [Must] [AUTH-5-11] 즉시 차단이 필요하면 차단 목록·세션 버전 등 서버 측 검증을 추가한다.

## 6. 소셜 로그인 — 요청·콜백

- [ ] [Must] [AUTH-6-01] 제공자가 지원하면 OIDC의 Authorization Code + PKCE(S256)를 사용한다.
- [ ] [Must] [AUTH-6-02] 제공자별 지원 기능과 검증 절차를 확인한다. 미지원 보안 기능의 대체 방안을 기록한다.
- [ ] [Must] [AUTH-6-03] state는 요청별 난수·일회용·유효기간을 적용하고 시작 브라우저에 연결한다.
- [ ] [Must] [AUTH-6-04] 콜백에서 state의 일치·만료·사용 여부를 검사한다.
- [ ] [Must] [AUTH-6-05] PKCE verifier는 요청별로 생성하고 해당 코드 교환에만 사용한다.
- [ ] [Must] [AUTH-6-06] OIDC nonce를 사용하면 요청에 연결하고 ID Token에서 일치 여부를 검사한다.
- [ ] [Must] [AUTH-6-07] Redirect URI를 정확히 등록한다. 와일드카드·임의 콜백 주소를 허용하지 않는다.
- [ ] [Must] [AUTH-6-08] 시작한 제공자와 콜백·발급자·토큰 교환 대상이 일치하는지 확인한다.
- [ ] [Must] [AUTH-6-09] Client Secret을 사용하는 코드 교환은 서버에서 수행한다.
- [ ] [Must] [AUTH-6-10] 인증 코드·토큰이 콜백 로그·분석 스크립트·Referer로 유출되지 않게 한다.
- [ ] [Must] [AUTH-6-11] 콜백 재전송·동시 호출로 인증 트랜잭션이 중복 소비되지 않게 한다.

## 7. 소셜 로그인 — 신원·계정 연결

- [ ] [Must] [AUTH-7-01] 프론트가 전달한 이메일·프로필·외부 사용자 ID만으로 로그인시키지 않는다.
- [ ] [Must] [AUTH-7-02] OIDC ID Token의 서명·iss·aud·exp·해당 nonce 및 필요한 azp를 검증한다.
- [ ] [Must] [AUTH-7-03] OAuth 전용 제공자는 공식 사용자 정보 API 등 지정된 절차로 신원을 확인한다.
- [ ] [Must] [AUTH-7-04] 외부 계정 키는 OIDC의 iss + sub 또는 제공자와 제공자 고유 ID를 사용한다.
- [ ] [Must] [AUTH-7-05] OIDC UserInfo의 sub가 ID Token의 sub와 일치하는지 검사한다.
- [ ] [Must] [AUTH-7-06] 이메일을 고유 식별자로 사용하거나 이메일 일치만으로 기존 계정을 자동 병합하지 않는다.
- [ ] [Must] [AUTH-7-07] 계정 연결 시 기존 계정 재인증과 새 외부 계정 인증을 모두 요구한다.
- [ ] [Must] [AUTH-7-08] 외부 계정 식별자에 DB 유일성 제약을 적용한다.
- [ ] [Must] [AUTH-7-09] 연결 해제 시 재인증을 요구하고 마지막 로그인 수단 제거를 방지한다.
- [ ] [Must] [AUTH-7-10] 최소 scope만 요청한다.
- [ ] [Must] [AUTH-7-11] 제공자 API 호출에 필요한 토큰만 보관하고, 다시 사용할 토큰은 암호화해 저장한다.
- [ ] [Must] [AUTH-7-12] 외부 신원 검증 완료 후 우리 서비스의 세션·토큰을 발급한다.
- [ ] [Must] [AUTH-7-13] 서비스 로그아웃·제공자 로그아웃·연결 해제의 동작을 구분한다.

- [ ] [Must] [AUTH-7-14] 외부 이메일을 복구·보안 통지 등 소유 확인이 필요한 용도로 사용하기 전에 신뢰하는 제공자의 email_verified=true 또는 동등한 검증 상태를 확인한다. 누락·false·의미가 불명확하면 자체 이메일 검증을 수행한다. 검증된 이메일도 계정 자동 병합 근거로 사용하지 않는다.

## 8. 자체 비밀번호 — 저장·입력·복구

- [ ] [Must] [AUTH-8-01] Argon2id 등 비밀번호 전용 해시를 사용한다. 평문·양방향 암호화·단순 SHA 해시를 금지한다.
- [ ] [Must] [AUTH-8-02] salt 생성·해시 검증은 검증된 라이브러리에 맡긴다.
- [ ] [Must] [AUTH-8-03] 해시 비용을 운영 환경에서 측정하고 설정한다.
- [ ] [Must] [AUTH-8-04] bcrypt 사용 시 UTF-8 기준 72바이트 초과를 명시적으로 거부한다. 거부 시 글자 수가 아닌 UTF-8 바이트 기준 초과임을 안내한다.
- [ ] [Must] [AUTH-8-05] 비밀번호를 조용히 자르거나 임의로 공백 제거·변환하지 않는다.
- [ ] [Must] [AUTH-8-06] 회원가입·로그인·변경·재설정의 입력 처리 규칙을 일치시킨다.
- [ ] [Must] [AUTH-8-07] 긴 비밀번호·붙여넣기·비밀번호 관리자를 지원하고 흔하거나 유출된 비밀번호를 차단한다.
- [ ] [Must] [AUTH-8-08] 기존 해시·길이 정책 변경 시 기존 계정의 전환·복구 경로를 제공한다.
- [ ] [Must] [AUTH-8-09] 재설정 토큰은 안전한 난수로 생성하고 해시 저장·짧은 만료·일회용을 적용한다.
- [ ] [Must] [AUTH-8-10] 재설정 토큰 소비와 비밀번호 변경을 원자적으로 처리한다.
- [ ] [Must] [AUTH-8-11] 재설정 URL은 신뢰하는 고정 설정으로 생성한다. 요청의 Host를 그대로 사용하지 않는다.
- [ ] [Must] [AUTH-8-12] 비밀번호 재설정 후 기존 세션·갱신 자격을 폐기한다.
- [ ] [Must] [AUTH-8-13] 소셜 전용 계정의 비밀번호 추가도 재인증으로 보호한다.

- [ ] [Must] [AUTH-8-14] 비밀번호 변경은 현재 비밀번호 또는 정책상 동등한 최근 재인증으로 승인한다. 로그인된 상태만으로 변경을 허용하지 않는다.
- [ ] [Must] [AUTH-8-15] 비밀번호 변경 후 다른 세션·Refresh Token·Remember me 자격을 폐기한다. 유지하는 현재 세션은 재발급하고 Access Token의 차단 시점을 검증한다.
- [ ] [Must] [AUTH-8-16] 신규 비밀번호 정책은 단일 요소 인증 시 최소 15자, 항상 MFA와 함께 사용하는 경우 최소 8자로 설정한다. 문자 수는 Unicode 코드 포인트로 계산한다.
- [ ] [Should] [AUTH-8-17] 최대 허용 길이를 최소 64자로 설정한다. bcrypt의 72바이트 제한과 충돌하면 길이 검사를 완화하지 말고 Argon2id 전환을 계획한다.
- [ ] [Must] [AUTH-8-18] 대문자·숫자·특수문자 혼합을 강제하거나 근거 없이 주기적 변경을 요구하지 않는다. 유출·탈취 근거가 있으면 변경을 요구한다.

## 10. 감사 로그·탐지 — 공통

- [ ] [Must] [AUTH-8.1-01] 인증 성공/실패·MFA 등록/해제/복구·계정 연결·권한 변경·세션/토큰 폐기를 이벤트 유형·계정 식별자·시각·신뢰 경계에서 확인한 IP·결과·상관 ID와 함께 기록한다. 클라이언트의 임의 X-Forwarded-For를 신뢰하지 않는다.
- [ ] [Must] [AUTH-8.1-02] 로그 접근 권한·변조 방지·보존 및 삭제 기간을 설정한다. OTP·TOTP 비밀·토큰 원문은 기록하지 않는다.
- [ ] [Must] [AUTH-8.1-03] 실패 급증·한 IP의 다계정 시도·한 계정의 다수 IP 시도·갱신 토큰 재사용에 임계값·관측 시간·알림 대상·대응 절차를 설정한다.
- [ ] [Must] [AUTH-8.1-04] 모의 보안 이벤트를 발생시켜 로그 저장과 경보 수신을 확인한다. 알림 실패 시 재시도·운영 경보를 제공한다.

## 11. 네이티브 모바일 — 해당 클라이언트 제공 시

- [ ] [Must] [AUTH-8.2-01] 장기 토큰은 iOS Keychain 또는 Android Keystore로 보호하는 암호화 저장소에 저장한다. 평문 설정·로그·일반 백업에서 제외한다.
- [ ] [Must] [AUTH-8.2-02] Authorization Code + PKCE를 시스템 브라우저 또는 OS 인증 세션으로 수행한다. 임베디드 WebView로 제공자 자격을 수집하지 않는다.
- [ ] [Should] [AUTH-8.2-03] 제공자·OS가 지원하면 소셜 콜백에 검증된 App Links / Universal Links를 우선 사용하고 도메인-앱 연결을 검사한다.
- [ ] [Must] [AUTH-8.2-04] 커스텀 스킴 사용 시 역도메인 스킴·정확한 콜백 검증·PKCE·트랜잭션 바인딩을 적용하고 스킴 가로채기 테스트를 수행한다.
- [ ] [Must] [AUTH-8.2-05] 모바일 앱 내 Client Secret을 비밀로 간주하지 않는다. 앱에 서버용 시크릿을 포함하지 않는다.
