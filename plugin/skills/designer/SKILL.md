# Designer

출발점은 항상 실제 회사의 값이에요(ui-ref `company`). 새로 지어내는 색은 "왜 바꿨는지"가 붙어야 해요.

## 순서

1. **읽기** 저장소 안이면 먼저 봐요: 기존 CSS 변수·Tailwind 설정, 글꼴(`@font-face`, `<link>`), 로고·브랜드 색, `DESIGN.md`. 있는 값은 고정값이에요.
2. **브리프 확정** 모르는 게 결과를 가르면 `grill-me`로 물어요(보통 3문 안: 화면 유형, 대상·톤, 다크 모드 여부). 사용자가 회사나 느낌을 이미 말했으면 질문은 건너뛰고 확정 브리프만 보여줘요.
3. **참고 회사** ui-ref `company`를 불러요.
   - 회사 이름이 있으면 그 회사. 없으면 분야·느낌 키워드(영문: fintech, consumer, playful, minimal, korean …)로 찾고, 키워드에 없는 분야는 아는 회사 이름으로 2~3곳.
   - 후보가 둘 이상이면 `show-me` 1라운드(축: 팔레트)로 고르게 해요. 채팅 안 위젯이 기본이라 선택 버튼이 답을 바로 돌려줘요. 둘 다 아니면 다른 후보를 더 불러요.
4. **토큰 확정** 고른 회사 값을 그대로 두고, 브리프에 맞춰 바꾼 것만 적어요("토스 값에서 둥글기만 당근으로"). 필요하면 `show-me` 2·3라운드(둥글기, 밀도). 상태 색이 없으면 회사 값이 없다고 적고 danger `#d32f2f` success `#2e7d32` warning `#ed6c02`를 넣어요.
5. **컴포넌트** 브리프의 화면에 필요한 부품을 ui-ref `list`/`get`으로 찾아요. 각 부품은 한 줄: 용어 정의(동작·접근성 요점) + Tween 코드가 있으면 설치 명령. 헷갈리는 짝(Dialog↔Bottom sheet)은 `graph`로 한 줄.
6. **산출물** 저장소 안이면 파일을 기본으로, 아니면 물어요.
   - 파일: `DESIGN.md`(아래 틀) + `tokens.css`(`:root{}` 변수 블록, company가 준 것 그대로 + 바꾼 값)
   - Design System 아티팩트: Artifact quickstart(intent "other")로 타입을 받아 토큰·글꼴·컴포넌트 가이드를 넣어요. 시안·슬라이드가 자동으로 이 값을 따라요.
7. **검수** 대비 4쌍(본문/표면, 보조/표면, 강조 위 글자/강조, 강조/연한 강조)이 AA(4.5:1)인지, 글꼴 라이선스가 무료인지, 출처 줄이 있는지. 미달이면 그 자리에서 값을 고치고 바꾼 이유를 적어요. 더 깊은 검토는 `design:accessibility-review`, `design:design-critique`로 넘겨요.

## 토큰 역할

| 역할 | 변수 | 쓰는 곳 |
|---|---|---|
| 강조색 | `--primary` | 주요 버튼, 선택 상태, 링크 |
| 강조색 위 글자 | `--onPrimary` | 강조색 배경 위 글자·아이콘 |
| 연한 강조색 | `--primarySoft` | 보조 버튼, 선택된 칩 배경 |
| 표면 | `--surface` | 카드, 입력칸, 모달 배경 |
| 보조 표면 | `--surface2` | 구역 배경, 호버 배경 |
| 본문 글자 | `--text` | 제목, 본문 |
| 보조 글자 | `--muted` | 설명, 도움말 |
| 테두리 | `--border` | 입력칸·카드 테두리, 구분선 |
| 상태 | `--danger --success --warning` | 오류·성공·주의 (팔레트와 별개로 유지) |
| 둥글기 | `--r-sm --r-md --r-lg --r-btn` | 칩·배지 / 입력칸 / 카드 / 버튼 |
| 간격 | `--sp-xs … --sp-xxl` | 회사 값 그대로. 없으면 4·8·12·16·24·32 |
| 글꼴 | `--font-sans` | company가 준 스택 + `<link>` |

## DESIGN.md 틀

사이트(ui.leo0409.work) 내보내기와 같은 형식이라 서로 바꿔 쓸 수 있어요.

```
# DESIGN.md — <프로젝트>
<한 줄: 무엇을 위한 토큰인지, 날짜>
## 참고
출처: <회사> (oh-my-design 정리값, 회사 공식 파일 아님) · 바꾼 것: <항목 → 이유>
## 타이포그래피
글꼴·라이선스·font-family·불러오기 <link>·스케일(h1~body 크기/굵기/행간)
## 색
| 역할 | CSS 변수 | Hex | 쓰는 곳 |  (상태 색 포함)
## 모서리 둥글기 / 간격
## 명도 대비
| 조합 | 대비 | AA |
## 컴포넌트
- <부품>: <정의 한 줄> · <설치 명령 또는 "직접 구현">
## 사용 원칙
강조색은 가장 중요한 동작에만 / 강조색 위엔 onPrimary만 / 상태 색은 팔레트와 별개 / 움직임은 prefers-reduced-motion 존중
```

## 규칙

- 회사 값을 쓸 때 출처를 꼭 적어요. 디자인 권리는 그 회사에 있고, 참고값이에요.
- "미검증" 회사 값은 그대로 써도 되지만 DESIGN.md 출처 줄에 "미검증"을 남겨요.
- 다크 테마는 회사 자료에 짝이 없으면 만들지 않아요. 필요하면 어두운 테마 회사(30곳)를 따로 골라요.
- 페이지를 실제로 코딩하는 단계는 이 스킬 밖이에요. 토큰과 컴포넌트 목록을 넘기고 `frontend-design`이나 일반 구현으로 이어요.
